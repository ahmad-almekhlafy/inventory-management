System Architecture

A two-tier demo app: a Vue 3 single-page app talks to a stateless FastAPI service over REST. There is no database. JSON files are loaded into memory once, when the server starts.

Data Flow

What happens when a user changes a filter, for example selecting "Tokyo" as the location on the Dashboard.

1

User changes a filter Client

FilterBar.vue writes to refs in useFilters.js. The refs are declared at module scope, so every view shares one filter state that persists across route changes.

2

The view's watcher fires Client

Each view watch()es the filter refs it cares about and calls its loader. Inventory watches only location and category. Dashboard watches all four.

3

The API client builds the request Client

api.js drops any filter set to 'all' and turns the rest into query params. The Dashboard sends four requests in parallel with Promise.all.

4

FastAPI filters in memory Server

apply_filters() matches warehouse exactly and category/status case-insensitively. filter_by_month() does a substring match on order_date and also accepts quarter keys such as Q1-2025.

5

Pydantic validates the response Server

Endpoints that declare a response_model are serialized against it. Summary and report endpoints return plain dicts.

6

Computed properties derive the UI Client

Raw responses go into refs (allOrders, inventoryItems). KPIs, charts, and tables are computed() from those refs, so they re-render automatically.

Example request

// useFilters state
{ period: '2025-03', location: 'Tokyo',
  category: 'all', status: 'all' }

// api.getOrders(filters) sends
GET /api/orders?warehouse=Tokyo&month=2025-03

# main.py
filtered = apply_filters(orders, 'Tokyo', None, None)
filtered = filter_by_month(filtered, '2025-03')
return filtered   # validated as List[Order]

Frontend Structure

State is shared through module-level refs in composables instead of a store library such as Pinia.

useFilters

Holds the four global filters (period, location, category, status). Provides getCurrentFilters() to build the API payload and resetFilters() to clear them.

useI18n

Provides t('key.path') lookups against locales/en.js and ja.js, falling back to English. The locale is saved in localStorage, and the currency follows it (en = USD, ja = JPY).

useAuth

Mock current user (no real authentication). Profile fields and sample tasks are localized through useI18n.

Known Gaps

These mismatches between the frontend and backend turned up while investigating the code.

Frontend calls endpoints the backend does not implement
  • api.js defines /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (GET, POST). None of them exist in main.py, so these calls return 404. You can see the "Failed to load tasks" error in the console.
  • Dashboard.vue renders <PurchaseOrderModal>, but no such component exists, so "Create PO" does nothing.
  • views/Backlog.vue exists, but no route points to it.
  • The backend's PurchaseOrder and CreatePurchaseOrderRequest models are defined but never used by any route.
